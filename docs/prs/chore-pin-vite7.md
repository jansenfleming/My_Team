# chore/pin-vite7: pin vite 7 at the root

Author: architect. Branch: `chore/pin-vite7`. Base: `main` (80bf8ba). Root config only.

## Problem
Since B1, `packages/shared` depends on vitest 5 without vite. npm auto-installed the peer `vite@8.3.0` at the root. `apps/web` keeps vite 7.3.6 nested, but the hoisted `@vitejs/plugin-react@5.2.0` resolved the root vite 8, and the two mismatch. `npm run dev -w @site/web` returned 500 for every module (`Missing field moduleType, Plugin: builtin:vite-react-refresh-wrapper`). `npm test` and `npm run build` still passed, so gates did not catch it. Reported by frontend-engineer.

## What changed
- Root `package.json`: `"vite": "^7.3.6"` in `devDependencies` (per ADR 0001, vite stays on 7).
- `package-lock.json`: regenerated by `npm install`.
- ADR 0001: records the trap and the rule.

## Output seen (Node 22.12.0)
- Before: `npm ls vite` showed `@vitejs/plugin-react@5.2.0 -> vite@8.3.0 deduped` next to `@site/web -> vite@7.3.6`.
- After: `npm ls vite` shows only `vite@7.3.6` everywhere (deduped).
- `npm test`: web 7 passed, shared 243 passed, qa 9 passed. `npm run build`: web builds. `npm audit`: 0 vulnerabilities.
- `npm run dev -w @site/web`: `/`, `/src/main.tsx` and `/src/App.tsx` all return 200 (were 500). Server stopped afterwards.

## Follow-up
QA gates should include a dev-server smoke (module requests return 200), since build and tests do not exercise it.
